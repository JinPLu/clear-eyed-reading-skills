# 通用祛魅共享核心重构

> 状态：已定稿，可实施。B 已正式选定为下一轮 shared core 方向，C 仅作按需路由；实现尚未完成，对应任务保持 active。

## Decision context and criteria

当前 Skill 把“祛魅”过多地写成“主张—证据—边界”的核对，因此容易把它收窄成证据范围审计。用户要解决的原始问题更根本：拿回作者框架之外的解释权和评价权，脱掉术语、模块名和宣传语后，判断这项工作到底在做什么、能力或知识从哪里来、方案是否抓住问题结构、结果从哪来、结论凭什么成立、系统为何能做到它展示的事、相对前人真正新增了什么，以及这项新增应如何定性。边界和限制仍然重要，但只有在会改变贡献定性或读者使用方式时，才作为修正项进入收束，而不是祛魅的独立主轴。

新设计需要同时满足以下标准：

- 能跨方法/系统、实证/因果、理论、临床、定性、资源/数据集/benchmark、综述/评论等类型复用同一问题意识；
- 不把易懂、祛魅、正式审稿和“毒舌式”挑错混成一个目标；
- 先重建问题、答案、机制、能力来源和贡献，再处理宣传收窄与适用边界；
- 允许祛魅提高评价：如果作者框架遮住了真正的结构性贡献，去命名化后可以更清楚地看见其重要性；
- 保留 canonical shared core + quick/deep profile + 生成自包含 Skill 的架构，只重定义共享语义及相应输出、README、eval 契约；
- 不把内部核验过程固化成用户可见清单，也不把通用核心写成平台或 AI 系统专属流程。

## Current synthesis

### 1. 祛魅究竟要夺回什么

祛魅首先是一次**去框架化的再理解**。读者应能在不依赖论文自命名的情况下回答：问题是什么，答案是什么，机制怎样把输入变成结果，哪些能力来自数据、先验模型、规则、人工选择、仪器或后处理，作者真正改变了哪一段问题结构。它还要求从作者的“印象管理”中抽离出来：识别作者希望读者形成的印象，随后用独立问题和竞争性解释检验该印象是否值得保留。

这与相邻概念的边界如下：

- **易懂**解决“读者能否形成、运行并复述正确心智模型”；祛魅解决“这个心智模型是否脱离了术语、品牌和叙事后仍然成立”。易懂可以没有足够祛魅，祛魅也不能以故意讲晦涩代替易懂。
- **边界/限制**回答结论在哪里不成立或不能外推。它是定标工具；只有会改写贡献成色、归因或使用方式时，才应改变总评，不应预设一张限制清单决定评价。
- **正式审稿**要对论文是否满足发表标准作独立、规范的评议，可能覆盖方法、统计、伦理和报告完整性；祛魅的重点是夺回问题、机制、来源、贡献与结果从哪来的解释权，不等于录用建议或逐项审稿。
- **毒舌/挑错**把怀疑、反讽或问题数量当成表现；祛魅可以指出关键水分，也可以在拆掉包装后提高评价，唯一标准是判断是否更接近工作实际。

因此，祛魅不是“把结论写窄”，而是把评价从作者提供的标签和气势中移回问题结构、真实增量与结果原因。

### 2. 方案比较与推荐

| 方案 | 实质做法 | 优点 | 结构性风险 | 结论 |
| --- | --- | --- | --- | --- |
| **A 当前主张—证据—边界中心** | 先按作者主张找证据，再主要收窄结论范围，边界承担祛魅主体 | 与现有 core 接近，易于实施；对证据不足的外推有保护 | 把祛魅降格为 boundary audit；无法稳定回答能力来源、问题结构、真实贡献和“结果从哪来、结论凭什么成立、系统为何能做到”；容易只把结论写窄 | 不作为共享主干，可保留为结果收束的一部分 |
| **B 通用拆解—来源—贡献—结果从哪来核心** | 先识别作者想造成的印象，去命名化重构问题/答案/机制，追踪能力来源，判断问题—解法契合与贡献，再讲清结果从哪来和其他可能解释，最后才定边界 | 跨学科复用；能解释“到底是什么”和“为什么有效”；允许贡献被上调或下调；边界回到正确位置 | 需要在共享 core 中写清判断顺序和证据契约；若实现成固定清单会变得机械 | **推荐为共享主干** |
| **C 按研究类型建立审计模板** | 为方法、因果、理论、临床、定性、资源、benchmark、综述分别建立字段和审计表 | 类型内的证据习惯更贴近；复杂工作可按需加深 | 模板爆炸、跨类型迁移差；内部表格容易泄露为用户清单；把字段误当成阅读思维 | 仅作为 B 之上的按需路线，不取代通用主干 |

推荐采用 **B 为共享主干、C 仅作按需路线**。C 的类型差异应体现在选取证据和展开叙事时，而不是复制八套互不相容的核心。A 的边界核验继续存在，但被放在贡献与归因之后。

### 3. 通用主干：从作者印象到可解释、可评价的工作

共享 core 的内部判断顺序建议保持以下语义链；输出不必逐项显示：

1. **识别作者希望读者形成的印象**：包括中心主张、贡献词、性能或现象叙事，以及读者可能被引导忽略的中间环节。
2. **去命名化重构问题、答案和机制**：用普通语言重述输入、目标、困难、解法和因果/推理链；模块名翻译不是拆解，必须说明每一部分实际做了什么。
3. **追踪能力或知识来源**：逐项区分新方法自身、训练/观测数据、外部模型、先验假设、规则、人工挑选、仪器、标注、后处理和评测设计的作用，不把能力来源错误归给论文最响亮的模块。
4. **判断问题—解法契合与科学品味**：方案是否抓住问题的结构性困难，简化是否保留关键变量，评价设计是否问到了真正的问题；简单或工程化不等于低级，复杂也不等于深刻。
5. **用两个不同反事实确定贡献类型与成色**：先做去命名化反事实——**(a)** 去掉术语和品牌后，这项工作在普通语言中到底是什么；这一步负责让问题、答案和机制脱离作者框架，不能直接当作贡献。再做贡献反事实——**(b)** 如果从领域中拿掉这篇工作，后续理解、实践、测量或研究选择具体会失去什么；只有这个失去什么的反事实用于确定贡献类型和成色。随后判断它属于新问题、新现象/发现、新测量/数据资源、新表示、新机制/理论、新证据、新工具/系统集成、新综合/解释、可靠负结果或复现中的哪一种（可多种并存），以及新增是否足以改变实践、理解或后续研究。
6. **讲清结果从哪来，并检查其他可能解释**：把主要结果拆成可能的贡献机制、数据/资源、评测、选择偏差、规模效应、实现细节或偶然性；性能高不能自动说明哪种机制造成了它，需说明哪些解释被排除、哪些仍在。
7. **最后收窄宣传、范围和边界**：只保留会改变贡献定性、归因、复现/复核或使用方式的限制；将“作者声称了什么”与“读者可以安全带走什么”并置。

这条链既不是固定用户清单，也不是正式审稿流程；它是 shared core 用来恢复判断顺序的隐形骨架。

### 4. 贡献类型不预设高低

贡献判断应至少能容纳以下类型：

- 新问题或新任务定义；
- 新现象、新发现或新经验事实；
- 新测量、数据资源、数据集或测量协议；
- 新表示、表征或可操作的视角；
- 新机制、新理论、模型或可检验假设；
- 新证据，包括更强识别、关键对照或跨条件验证；
- 新工具、系统集成、工程路径或可用基础设施；
- 新综合、新解释或把分散事实连成可检验框架；
- 可靠的负结果、失败边界或对流行说法的纠偏；
- 高质量复现、再分析或使结论可复核的工作。

工程集成不能因为“已有部件”就天然判低；应问它是否解决了真实部署/测量/组合问题，是否使能力从不可用变为可用，是否揭示了新的系统性约束。反过来，理论或机制标签也不能仅因形式漂亮就自动升格，必须看其是否承载结论、预测或解释增量。

### 5. 跨类型路由：同一问题，不同证据表达

所有类型共享“到底在解决什么、真实改变什么、为什么能成立”的问题，但不硬套同一字段或同一实验逻辑。类型路由只决定需要强调的证据和叙事方式：

| 类型 | 重点追问 | 不应机械套用 |
| --- | --- | --- |
| 方法/系统 | 问题结构、输入输出、组件来源、系统瓶颈、模块组合是否产生新能力 | 只按单模块新颖性评分 |
| 实证/因果 | 现象是否可靠、识别/对照是否支撑归因、替代解释是否被排除 | 把相关性结果套成机制证明 |
| 理论 | 假设承载什么结论、证明或反例改变了什么、适用条件是否透明 | 把形式复杂度等同于贡献 |
| 临床 | 人群、干预、对照、结局、风险收益和可实施性如何共同决定贡献 | 把单一显著性或指南位置当总评 |
| 定性 | 研究对象、材料、解释框架、反例和研究者位置如何支持洞见 | 强迫其产生量化 benchmark 字段 |
| 资源/数据集/benchmark | 资源解决谁的测量或比较缺口，定义、覆盖、泄漏、基线和使用成本是什么 | 因没有单一模型提升就判低 |
| 综述/评论 | 是否提供新的问题地图、综合解释、分类或可检验议程，证据选择是否透明 | 只按原创实验或引用数评价 |

### 6. Quick 与 Deep 的输出契约

Quick 和 Deep 继续共享同一分析和证据标准，只改变向读者展开的粒度，不把 quick 降成旧式 boundary audit。quick 建议贴近用户曾偏好的阅读顺序：

> 一句话定性 → 真实贡献 → 带你读懂 → 结果从哪来、结论凭什么成立或系统为何能做到 → 承重问题/水分 → 五维与一句总评

在实际呈现中可压缩为五个自然段或相邻模块：

1. 一句话定性与问题/答案的去命名化重构；
2. 真实贡献（含能力来源和贡献类型）；
3. 用最短路径带读者跑过核心机制；
4. 结果从哪来、结论凭什么成立或系统为何能做到，以及最关键的材料和其他可能解释；
5. 承重问题/水分、适用范围、用途与五维判断。

这里的“承重问题/水分”不是独立的边界主轴，而是前述贡献与归因判断的必要修正。Deep 仍采用自然叙事：先定位工作，再讲问题，展开去命名化机制、能力来源和类型相关细节，解释结果与替代解释，最后形成贡献、范围和评分判断；不把内部主干输出成章节清单。若某一类型需要 C 路线的额外证据，Deep 可在自然叙事中按需展开，quick 只保留会改变定性的部分。

### 7. 五维评分只记录已经形成的判断

完整研究论文可继续记录五个独立维度，但评分必须是已完成判断的摘要，不是机械平均或替代推理：

- **创新与意义**由真实贡献类型、问题结构和反事实增量定调；不是由标题、模块名或性能数字直接决定；
- **严谨性**检验主张、机制和归因是否站得住，是否有足够对照、识别、证明或复核路径；
- **清晰度**记录问题、机制、来源和结论是否可理解，不因文本短或图好看自动得高分；
- **可复现/可复核性**记录材料、数据、代码、协议或推理链是否足以复核，不与创新性做补偿；
- 不计算总分，不把五维做平均，也不让清晰度或可复现性机械抵消贡献判断；材料不足时说明缺口，非研究文章不强套该评分。

### 8. 更服务祛魅的多路调研

在可并行的环境中，当前 `field / nearest / counter-precedent` 三路应重命名并调整问题，使调研直接服务上述判断：

1. **问题与评价标准谱系**：追踪这个问题如何被定义、测量、比较和评价，哪些标准是历史形成的，哪些是本文自定的；不把领域共识直接当作本文贡献。
2. **贡献、组件与思想谱系**：围绕去命名化后的贡献原子，查找前人问题、组件、表示、机制、数据资源、系统组合和解释框架，比较真正改变了哪一段。
3. **结果从哪来与其他可能解释**：寻找可解释同一结果的替代机制、反例、负结果、边界条件、测量或选择偏差，检查作者的解释是否超过材料。

三路仍保留多路径候选发现、主 agent 统一冻结论文指纹并阅读全文、会改变判断的候选需完整比较、停止条件和能力降级规则：至少用两类独立发现路径挑战每个核心贡献；读完所有会改变创新/贡献/归因判断的候选；再扩展一轮关键词、引用或相邻术语不再出现改变判断的新候选；记录全文、数据库、语言和时间缺口。无 subagent 时按三路顺序化执行并披露未独立交叉验证；无外部检索时退回材料内阅读，不把未知写成不存在。

## Anti-degeneration rules

实现和验收必须保留以下反退化控制：

- 不能只把作者结论写窄，就声称完成祛魅；必须能说明问题结构、能力来源、真实增量或结果从哪来；
- 不能把作者模块名翻成中文、换几个同义词就算拆解；必须重构输入、操作、输出及其必要性；
- 不能用限制清单决定总评；限制只在改变贡献定性、归因、复核或使用方式时提高权重；
- 不能因工作简单、工程化、早期概念验证或负结果而自动贬低；判断它是否解决了真实缺口、提供了可靠信息或改变了后续选择；
- 不能因为性能高就接受机制归因；要挑战数据、评测、规模、选择、实现和替代解释；
- 不能把通用核心写成平台、模型或 AI 系统专属；跨类型路由必须保留问题共同性和类型差异；
- 不能把内部路线、证据卡和评分过程原样倾倒给用户；输出应是自然、可复述的解释与判断。

## Regression and real-acceptance matrix

回归不检查固定标题或内部清单，而检查可观察的判断是否发生。至少覆盖以下路径：

| 案例 | 必须可观察的断言 |
| --- | --- |
| 系统拼装但宣传很大 | 输出拆开已有组件、数据/外部模型/后处理来源，仍判断系统组合是否解决真实瓶颈；不因集成自动贬低，也不接受宣传原话作为贡献 |
| 真正新表示但提升有限 | 输出先说明表示改变了什么问题结构，再承认性能增益有限；不因数值小自动否定表示贡献 |
| 早期概念验证 | 区分概念性新意与验证范围，指出尚未证明的外推；不把早期阶段自动写成低价值或成熟系统 |
| 理论假设承载结论 | 明确哪些假设使结论成立、假设是否被检验/可放宽；不以形式复杂度代替理论贡献 |
| 临床研究 | 按人群、干预、对照、结局、风险收益和实施条件解释贡献；不把单一显著性当作总评 |
| 定性研究 | 从对象、材料、解释框架、反例和研究者位置讲清洞见；不强行要求量化字段 |
| benchmark 定义胜利 | 识别任务定义、指标、泄漏/覆盖和比较规则本身的贡献；不只看模型提升，也不把定义便利写成普适能力 |
| 资源、负结果或复现 | 说明资源填补的测量/可复核缺口，或负结果/复现如何改变信念；不因没有新模型或正向提升自动贬低 |
| 博客/评论 | 仍可去命名化重构问题、来源、论证和真实增量，但不强套研究论文五维评分或假装有实验边界 |

跨案例的验收重点是：输出是否真正恢复解释权和评价权，而不是仅完成 boundary audit；quick/deep 是否来自同一判断，只有展开粒度不同；材料不足时是否诚实收缩；“祛魅”是否在合适案例中提高而非只降低评价。

## Architecture and implementation boundary

保留当前 canonical core + quick/deep profile + generated self-contained Skills 架构：

- `skill-src/core.md` 仍是唯一共享语义来源，本轮只重写其中祛魅主干、贡献类型、跨类型路由、归因与竞争性解释、调研三路和反退化契约；
- `skill-src/depth/quick.md` 只调整 quick 的读者结构与压缩规则，确保“一句话定性—真实贡献—带你读懂—结果从哪来、结论凭什么成立或系统为何能做到—承重问题/水分—五维与一句总评”可自然呈现；
- `skill-src/depth/deep.md` 只调整自然叙事中的展开重点，不把主干变成固定审计表；
