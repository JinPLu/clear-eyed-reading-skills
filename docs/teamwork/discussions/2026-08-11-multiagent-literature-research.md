# 祛魅阅读的多 subagent 领域与近邻调研

> 状态：已定稿，可实施。三路并行调研、证据卡、停止条件与能力降级均已确认；后续只执行实现和最小验收。

## Decision context and criteria

用户明确否决“固定找 4 篇”作为论文阅读前的调研规则。对一篇陌生论文，先找到少量看似相关的文章并不能保证读懂其领域位置、近邻工作或真实增量；需要按不同证据问题分工调研，直到足以判断本文的核心结论、创新和贡献。这里的目标不是做一篇独立的系统综述，而是为同一篇论文建立一份可追溯、可合并、能支持祛魅判断的事实包。

设计需要同时满足：

- 不以固定篇数冒充充分调研；
- 把领域脉络、直接近邻和可能反证分开搜集，避免单一路径的盲点；
- 让 subagent 交付可合并的证据，而不是各写一篇互相重复的评论；
- 由一个主 agent 统一冻结论文身份、定义贡献原子、阅读全文和最终成文；
- quick 与 deep 共享同一份事实包，只改变向读者展示的粒度；
- 当材料、工具或并行能力不足时，结论要收缩并明确缺口，而不是假装完成了广泛检索。

## Current synthesis

当前确认的默认架构是三路并行、输入隔离、主 agent 统一合并：

1. **领域脉络路**：回答本文所处的问题谱系、常见任务/评价方式、关键转折和术语边界，帮助零基础读者知道“这个问题在领域里是什么”。
2. **近邻工作路**：围绕本文的论文指纹、贡献原子和方法组件寻找直接可比的基线、前后继、同问题不同路线和最接近的替代方案，回答“作者真正改变了什么”。
3. **反证先例路**：寻找会削弱或限定本文主张的失败案例、负结果、已知边界、相反证据或条件不同的研究，回答“结论在哪些范围内不能直接外推”。

三路 subagent 的输入彼此隔离，不互看对方的中间结论；每路只交付结构化证据卡，不各自撰写完整评论。这样做不是为了制造三种意见，而是让不同搜索问题保留独立的发现路径，减少先看到某个结论后沿着它补证据的偏差。

主 agent 负责以下不可拆分的判断与写作职责：

- 先冻结目标论文的身份指纹（标题、版本、作者、时间、链接/DOI 等）和待核验的贡献原子，避免不同版本或相似标题串线；
- 合并三路候选，去重并标记候选与论文的关系；
- 对真正可能改变判断的候选阅读全文，而不是只凭标题、摘要或图注纳入结论；
- 维护共享证据账本，区分论文陈述、直接观察、外部事实、分析判断与未知；
- 对实质冲突复用已经完成的 subagent 任务，要求其只裁决一个明确命题并返回证据，不组织投票或无限辩论；
- 依据同一事实包分别生成 quick 和 deep，quick 走最短理解路径，deep 展开必要背景、方法、公式、实现、图表与实验细节，但不改变事实标准。

这与现有“共享阅读核心与输出配置解耦”决策一致：调研和判断属于共享核心，摘要/精读只是展示粒度不同。参见 [祛魅阅读共享核心与输出配置解耦](2026-08-11-reading-core-output-separation.md)。

## Evidence contract

每个 subagent 的交付是可拼装的六字段证据卡，而不是一篇小论文：

- **命题或候选**；
- **原始来源与定位**（正文、图表、实验、附录、代码或可靠外部来源）；
- **为何相关**；
- **与目标相同/不同**；
- **对结论影响**；
- **未知**。

主 agent 维护内部紧凑证据账本即可，不把检索过程改写成 PRISMA 表或用户可见的流程清单。

主 agent 不应把“搜到过”当成“已验证”，也不应把三个 subagent 都没有找到反例解释成“没有反例”。候选是否纳入事实包，取决于它是否改变核心结论、创新、贡献或适用边界的判断。

## Questions and decisions

### 已确认

- 不采用固定找 4 篇的规则；调研数量由理解论文所需的证据覆盖决定。
- 默认启用三路并行：领域脉络、近邻工作、反证先例。
- 三路输入隔离，不互看彼此结论；每路只交结构化证据卡，不各写完整评论。
- 主 agent 冻结论文指纹和贡献原子，合并候选，阅读全文判断相关候选，维护共享证据账本并唯一成文。
- 实质冲突时，复用已完成的 subagent 对单一命题做针对性裁决；不投票，不进行无边界的多轮争辩。
- quick/deep 使用同一事实包，只改变输出展开粒度，不各自重新搜索出两套事实。

### 已确认的候选发现、停止与降级规则

- **候选发现多路径**：围绕每个核心贡献原子，至少用两类独立发现路径发起挑战；路径可来自关键词/标题、引用网络、相邻术语或同等独立入口，按论文类型取真正相关的路径，不把固定篇数当作覆盖证明。
- **停止条件**：同时满足以下四点才停止扩展候选：
  1. 每个核心贡献原子至少经两类独立发现路径挑战；
  2. 所有会改变创新或贡献判断的候选都已阅读全文，并可按任务、机制、数据/评测和真实差异逐轴比较；
  3. 再扩展一轮关键词、引用和相邻术语后，不再出现会改变判断的新候选；
  4. 披露全文、数据库、语言和时间范围的缺口，结论只表述为“在已检索范围内”。
- **没有 subagent 能力时**：仍执行领域脉络 → 近邻工作 → 反证先例的顺序化检索，但明确披露结果不具备独立并行验证；没有外部检索能力时退回材料内阅读，并明确领域定位、近邻关系和创新标记未经独立外部验证。

## External design references

以下来源只作为本轮架构的外部方法参考，不证明本项目的具体流程已经被这些来源验证，也不把论文阅读任务夸成系统综述：

- [OpenAI Agents SDK — Agent Orchestration](https://openai.github.io/openai-agents-js/guides/multi-agent/)：区分由中心 manager 调用 specialist 的 agents-as-tools 与交接式 handoff；本项目采用前者的“主 agent 保留最终合并和用户沟通控制”这一可比思路。
- [Anthropic — How we built our multi-agent research system](https://www.anthropic.com/engineering/multi-agent-research-system)：公开描述了复杂研究问题中的并行探索、协调与可靠性挑战；其内部评测数字不外推到本项目。
- [Cochrane Handbook, Chapter 4: Searching for and selecting studies](https://www.cochrane.org/authors/handbooks-and-manuals/handbook/current/chapter-04)：强调系统、全面、可记录的检索与选择，并把多种识别来源作为互补手段；本项目借鉴“记录搜索与选择边界”，不宣称执行 Cochrane 综述。
- [Wohlin (2014), Guidelines for Snowballing in Systematic Literature Studies](https://www.wohlin.eu/ease14.pdf)：说明前向/后向引文滚雪球可作为发现相关研究的一条路径，同时提醒搜索策略应结合具体范围；本项目将其视为候选发现入口之一。
- [PRISMA-S](https://pmc.ncbi.nlm.nih.gov/articles/7839230/) 与 [TARCiS statement](https://www.bmj.com/content/385/bmj-2023-078384)：提供检索过程和引文检索报告的透明记录思路；它们是记录规范参考，不是本 Skill 的固定输出模板。
