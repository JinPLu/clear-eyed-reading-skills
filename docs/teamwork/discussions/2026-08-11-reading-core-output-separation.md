# 祛魅阅读共享核心与输出配置解耦

> 状态：已定稿，可实施。架构决策已冻结；后续仅执行同步与最小验收，不再改写本 Discussion 的方向。

## Decision context and criteria

用户指出，摘要读法与精读读法本质上是同一套“易懂 + 祛魅”阅读方法，主要差别在于输出的细粒度，而不是两套互不相干的推理逻辑。后续还可能增加 HTML 版本，因此需要把共享的阅读核心与输出要求拆开，使不同深度和不同呈现格式能够复用同一套语义，而不复制整套阅读逻辑。

当前约束是：Codex Skill 没有原生继承或 `include` 机制；项目又要求每个已安装 Skill 自包含，且 quick/deep 不直接合并。实现方式必须同时满足以下标准：

- “易懂 + 祛魅”的阅读判断只有一个可维护的核心来源；
- 摘要与精读仍保持各自清晰的显式入口和深度边界；
- Markdown 对话输出与未来 HTML 输出只改变呈现/粒度，不重新实现阅读逻辑；
- 生成或同步后的已安装 Skill 仍是宿主可独立读取的自包含文件；
- 不因抽象层增加而把用户可见输出变成冗杂的内部清单。

## Current synthesis

当前采用两条正交轴来理解系统：

1. **阅读深度**：摘要 / 精读。它决定核验范围、解释粒度和覆盖深度；两者共享“易懂 + 祛魅”的阅读核心。
2. **呈现格式**：对话 Markdown / 未来 HTML。它决定内容如何组织和渲染，不应复制或改写阅读核心。

用户已确认采用 **A：canonical shared core + 生成/同步到自包含 Skill** 的源码组合架构。这意味着仓库维护一份 canonical core，再根据不同深度和入口生成或同步出各自完整、自包含的 Skill 文件；未来 HTML 也应消费同一核心语义，而不是另写一份阅读方法。

shared core 的边界已进一步确认，并采用“核心再扩展、再加五维评分”：核心不仅负责从问题、方法和主张—证据关系建立正确心智模型，还统一辨认真增量、能力来源、证据分量与适用边界；要求实际查看关键图表、按功能理解关键公式、让实验围绕核心结论与贡献展开，并区分论文陈述、直接观察、分析判断和未知，同时保留材料核对与安全边界。复杂方法的贯穿具体例子、纯文字难以讲清时的一张真正可渲染示意图，以及完整研究论文默认的创新性、严谨性、意义、清晰度、可复现性/可复核性五维评分，也属于共享核心；非研究文章不强套评分。

quick 与 deep 使用相同的完整分析和证据标准，均应尽量读取完整材料并实际查看关键图表；差异只在输出展开粒度。quick 输出理解结论的最短路径——问题、方法本质、决定性证据、真实贡献、关键边界和评分，支持细节只在会改变判断时出现；deep 展开同一路径，补足必要背景、模块与公式、影响复现的细节，以及主实验和补充实验各自增加的理解。摘要不是少读后猜，而是完成判断后少展示；精读也不是另一套更严苛的审计。

quick profile 的输出骨架已固定为五段：1）问题与必要背景；2）方法怎么工作；3）真正新增了什么；4）决定性证据说明了什么；5）祛魅结论与五维评分。开头可以有一小段全文定位，但不另算章节；贯穿例子和必要图示嵌入方法段；主要水分、适用范围和使用方式合并到最后判断，避免旧七段重复。固定骨架只控制读者顺序，不把内部核验流程或清单暴露给读者。

已确认的源码布局与本轮范围为：`skill-src/core.md`；`skill-src/depth/{quick,deep}.md`；`skill-src/output/chat.md`；以及 `scripts/sync_skills.py`。脚本确定性拼装 `core + depth + output`，生成两个现有、自包含的 Skill `SKILL.md`；生成文件提交仓库，安装和运行不依赖 Python 或共享目录。本轮只实现 chat 输出；HTML 仅预留未来新增 `skill-src/output/html.md` 的扩展位置，不在本轮设计或生成 HTML。

同步规则与入口元数据也已确定：`skill-src` 是唯一权威来源，只修改源文件；`scripts/sync_skills.py` 写入生成结果，并支持 `--check` 仅检测漂移。每个 depth 源文件同时保存对应入口的 name、description 和 interface metadata；同步脚本统一生成对应的 `SKILL.md` 与 `agents/openai.yaml`，并为两个入口写入 `policy.allow_implicit_invocation: false`。

chat renderer 只负责跟随用户语言、输出清晰 Markdown、确保图示在当前界面真正渲染，以及让引用贴近其支撑的判断；它不包含阅读逻辑，也不强制图标、表格或评分卡样式。

候选比较仍保留如下，供后续维护时理解为何未选：

- **A（已选）**：canonical shared core + 生成/同步到自包含 Skill。集中维护、减少语义漂移，并保留宿主所需的自包含安装结果；代价是需要明确 core、profile、生成/同步边界。
- **B（未选）**：每个 Skill 独立复制 core。初期最简单，但摘要、精读和 HTML 版本会逐渐漂移，修复需多处同步。
- **C（未选）**：合并成单个多模式 Skill。表面上重复最少，但违反当前 quick/deep 不直接合并的项目边界，也会使显式入口和深度语义变复杂。

## Questions and decisions

### 已决策

- 摘要与精读共享同一套“易懂 + 祛魅”阅读核心。
- 阅读深度和呈现格式是两条正交配置轴；HTML 不复制阅读逻辑。
- 采用 A 架构：维护 canonical shared core，并生成/同步到自包含 Skill。
- B、C 不作为当前实现方向；原因分别是维护漂移和违反既定 quick/deep 边界。
- shared core 已包含共同读法、关键证据核验、必要视觉/公式/实验理解、材料与安全边界、贯穿例子、必要时的可渲染示意图，以及完整研究论文的五维评分。
- quick 与 deep 采用同一分析/证据标准，差别只在展示粒度：quick 压缩为最短理解路径，deep 展开同一路径所需的背景、模块、公式与实验细节。
- quick profile 已固定五段输出骨架：问题与必要背景；方法怎么工作；真正新增了什么；决定性证据说明了什么；祛魅结论与五维评分。全文定位可作为开头短段，例子/图示嵌入方法段，水分/范围/使用方式并入末段；骨架只约束读者顺序，不暴露内部核验清单。
- 已确认源码布局为 `skill-src/core.md`、`skill-src/depth/{quick,deep}.md`、`skill-src/output/chat.md` 和 `scripts/sync_skills.py`；确定性生成的两个自包含 `SKILL.md` 纳入仓库，运行时不依赖 Python 或共享目录。
- 本轮只实现 chat renderer；HTML 只预留 `skill-src/output/html.md` 的未来扩展位置，不在本轮设计或生成。
- `skill-src` 是唯一权威来源；只修改源文件，由同步脚本写入生成结果，并用 `--check` 检测漂移。depth 源保存入口元数据，脚本统一生成 `SKILL.md` 与 `agents/openai.yaml`，两个入口均禁止隐式调用。
- chat renderer 只处理语言、Markdown、可渲染图示和贴近判断的引用，不承载阅读逻辑，不强制图标/表格/评分卡样式。

### 延后范围与实施验证

- 摘要 profile 与精读 profile 的边界已经冻结为只控制展示展开程度，不降低分析和证据标准；quick 是完成判断后少展示，deep 是展开同一路径。quick 的展示顺序固定为上述五段，但这不改变共享核心或内部分析流程。
- HTML renderer 暂不设计或生成；未来如启动 HTML，再确认其调用/渲染接口，并确保消费同一 core。

架构文件策略已定；剩余工作转入后续实施验证，包括运行同步脚本、执行 `--check`、检查生成的自包含 Skill 与入口元数据，以及用 eval/真实论文验收共同核心和 quick/deep 的展示粒度。
