# 祛魅语义漂移因果诊断

> 状态：`fix-verified`。Debug 阶段已定稿；修复已通过独立语义验收和同材料 quick/deep 前向核验。本文件保留因果诊断，并记录修复验证的证据与剩余限制。

## Failure and operating boundary

### 期望

“祛魅”应让读者拿回作者框架之外的解释权和评价权：去掉术语、模块名和宣传语后，仍能看清论文在解决什么，能力或知识从哪里来，问题与解法是否契合，真实增量是什么，以及结果从哪来、结论凭什么成立、系统为何能做到它展示的事。贡献与创新负责定调；边界和限制只在会改变贡献定性、归因、复核或使用方式时修正判断。

### 观察到的结果

当前 shared core 是可读性良好的 **evidence-boundary audit**：它擅长区分主张、材料、证据边界和可安全外推的范围，但没有把去作者框架化、能力来源、问题—解法契合、真实贡献和结果从哪来作为祛魅的主轴。因此，输出可以诚实而清楚，却仍把“祛魅”收窄成“校准主张与证据”。

### 首个坏 owned boundary

在逐项确认“易懂 + 祛魅”时，agent 没有回放用户的原始定义，擅自将其操作化为：**“易懂负责心智模型，祛魅负责校准主张与证据。”** 用户随后确认了这一错误框架；这条确认链是目前可归责的正式冻结边界。

更早的语义分叉可追溯到另一个线程把以下三层定为祛魅内核：**“作者声称了什么、材料直接显示了什么、读者据此可以推到哪里。”** 这三层本身是有用的证据边界，但把它们冻结为祛魅主体，已经把目标从去框架化再理解偏向 boundary audit。它是较早分叉，不取代上述确认链作为首个坏 owned boundary。

### 运行边界

原始 Debug 轮次只做诊断和记录：无文件修复、无探针、无行为变更。随后依据已 final 的 `universal-demystification-core` 实施修复，并由独立 Strict Review 及前向核验确认；本文件不把诊断阶段的观察误写成当时已完成修复。

## Causal picture

### 因果链

```text
局部图/公式/可读性退化触发
  → 将“易懂 + 祛魅”错误定义为“心智模型 + 主张/证据校准”
  → 局部确认冻结该定义
  → deep 重写与 shared-core 抽象时未重新冻结全局目标
  → counter-precedent、实验边界和三路研究被吸收到审计链，进一步放大 boundary-audit 形态
  → eval 与真实论文测试主要验证覆盖、图、公式、三路研究和诚实收缩，不能区分 boundary audit 与真正祛魅
  → README 与小红书叙述把已运行、可检查的审计能力固化为对外价值表述
```

scope expansion 本身是已授权的架构变化，不是未经许可的越界；问题在于扩展 shared core 时没有重新冻结“祛魅究竟要解决什么”，所以扩展的是覆盖面和证据链，而不是已确认的语义目标。

### 假设 standing

- **H1 首因：confirmed。** 正式冻结的错误操作化发生在“易懂 + 祛魅”确认链；它解释了为什么后续规则普遍诚实、可读，却仍以 evidence-boundary audit 为中心。
- **H2 scope expansion：confirmed but authorized。** deep 重写、shared core、quick/deep 解耦、三路研究和文档同步均在授权范围内；因果问题不是扩展本身，而是扩展时未重冻全局目标。
- **H3 semantic test gap：confirmed。** 现有 eval 与真实测试能观察覆盖、图、公式、研究分工和材料不足时收缩，却没有能区分“只收窄边界”与“真正夺回问题、来源、贡献和归因解释权”的语义判别样例。
- **H4 research tracks：amplifier。** 三路研究和 counter-precedent 增加了可追溯证据与覆盖，但在错误目标下放大了审计形态；它不是首因。
- **H5 README/promo：solidifier。** README 与宣传把已验证的审计、图示、公式、三路研究和边界表达固化为产品价值叙述，使漂移对外稳定化；它不是首因。

## Discriminating observations

以下观察区分了“只是证据审计”与“真正祛魅”，并支持上述 standing：

1. 用户多次要求收回过度复杂、过度严苛和清单化的方向：**“不需要搞得过于复杂，讲清楚问题，祛魅地讲懂了才是重点。”** 这说明目标不是增加审计字段或问题数量。
2. 用户明确指出，agent 已经知道“祛魅”“易懂”，继续把自然语言拆成模板会制造读者看不懂的输出：**“agent应该是知道‘祛魅’、‘易懂’这种词的，你现在说反而会让他输出一堆让人看不懂的东西。第3项同理，也要重构。”** 这直接否定了把目标等同于可见清单的路径。
3. 用户把实验判断重新锚定到贡献，而非严苛审计：**“你需要锚定核心结论、创新、贡献来看待实验，然后其他实验有没有补充，而不是组合各种细节来回答这个文章又没有问题。”** 这与当前 evidence-boundary audit 的偏心相反。
4. 用户明确指出 quick/deep 的差异应是输出细粒度，而不是两套读法：**“精读和摘要读法只是输出细粒度不同，很多要求都是重叠的，我觉得需要将核心‘祛魅+易懂’和输出要求拆开。”** 这说明共享核心应承载语义目标，profile/renderer 才承载展开方式。
5. 初始线程曾给出有用但不充分的三层框架：**“作者声称了什么、材料直接显示了什么、读者据此可以推到哪里。”** 后续确认链没有把用户更根本的“问题、来源、真实增量、为什么成立”重新放回主轴，形成了可追溯的语义分叉。
6. 局部视觉/公式问题、可渲染图、公式功能命名、三路研究、真实论文测试和静态同步都能通过，而输出仍可能只是 boundary audit。这说明这些检查对覆盖和工程一致性有判别力，对“祛魅是否被正确理解”没有判别力；**一致不等于正确**。

### 决定性线程

- `019ff0f9-b853-7120-9ada-4ec798bd548b`：首次把“祛魅”讨论为可检验理解和证据边界，并出现“作者声称/材料显示/读者能推到哪里”的早期框架。
- `019ff148-496e-7190-84a5-a909591f3932`：逐项确认“易懂 + 祛魅”、高自由度和实验/证据表述；错误的心智模型与证据校准二分在此确认链中正式冻结。
- `019ff1c4-4c31-77e1-9c04-36795ceb54a7`：shared core、quick/deep 输出解耦、三路调研、真实论文/静态验收及 README 对外叙述形成闭环；这些表面验证了覆盖与一致性，却没有提供语义判别。

## Cause, next discriminator, and verification

### 已确认原因

首因是 **H1**：在没有回放用户原始定义的情况下，agent 将“祛魅”冻结为“主张与证据的校准”，并在之后的重写、共享核心抽象、研究分工、eval、真实测试和对外叙述中持续沿用该定义。H2 说明扩展是授权的但未重冻目标；H4、H5 分别放大并固化了结果；H3 解释了为什么既有验收没有拦住漂移。

### 遮蔽控制为何未能判别语义

以下控制均有合理作用，但都不能单独证明祛魅目标正确：

- **observed-failure-only**：避免凭空增加规则，却只能约束已观察到的失败；
- **高自由度**：减少清单化和过度模板，却不会自动恢复正确目标；
- **canonical single source**：减少 quick/deep 漂移，却可能把错误语义更一致地复制；
- **三路检索与 counter-precedent**：增加来源覆盖，却不能回答“覆盖的是哪一个目标”；
- **真实论文测试**：证明路径能跑通、材料可读和结果可用，却未区分 boundary audit 与去框架化再理解；
- **静态同步/一致性检查**：证明源、生成物和文档对齐，却不证明语义判断正确。

### 最小防复发控制

共享 core 升级时增加一张**语义冻结卡**，只保留四项：用户原话、明确非目标、一个正例、一个近邻反例。升级不得只复述旧 core，也不得以覆盖清单代替冻结。

在语义验收中加入同题两段判别样例：一段仅做 boundary-only audit，另一段真正回答问题结构、能力/知识来源、真实贡献和结果为何出现；验收必须能说出二者差异。静态检查、同步检查和图/公式/研究覆盖检查不能替代这一步。README、宣传或其他对外价值表述，只能使用已经通过该语义判别的表述。

### 修复验证证据

修复后的 Strict Review 先发现并闭合了两项 `REVISE` finding：配对近邻 eval 现在嵌入可判别的 boundary-only Candidate A 与独立重构 Candidate B；`skill-src/core.md` 现在把贡献和归因标为 provisional，先完成中性研究，再由主 agent finalize。

随后完成的 blind LiveWorld deep test 使用 arXiv v2 及其 appendix、官方 project/repo 和主要 lineage sources。其输出实际展示了去作者框架化的机制重构、能力/知识来源追踪、field-removal counterfactual 的贡献定位和结果从哪来的解释，满足语义判别所需的四个观察面。

同一材料的 quick/deep parity test 也已完成：两者给出相同的实质判断，deep 只展开更多细节，支持 shared core 与 profile 粒度解耦的行为契约。两项前向测试均未执行代码或做独立 reproduction。

因此，首因 H1 仍是已确认的因果解释，而修复状态现为 `fix-verified`：语义冻结、配对判别 eval、core 顺序和前向行为证据共同支持修复已经改变了原先的 boundary-audit 漂移。剩余限制是没有独立 reproduction，且 LiveBench 仍未发布；这些限制不被写成已观察到的失败。
